# Tailscale 또는 같은 LAN에서 원격 실습하기

연구실 Ubuntu 데스크탑 1대와 학생 Ubuntu 노트북 1대를 한 쌍으로 사용합니다.
학생별 Tailscale 설치·로그인, 영상·Play 확인과 공용 데스크탑 반납은 [0장 환경 설정](../isaacsim_basic/00_env_setting/README.md)을 따릅니다.
Tailscale로 연결할 때는 아래 모든 `--host`와 영상 클라이언트의 Server에 같은 **데스크탑 Tailscale IPv4**를 사용합니다.
데스크탑이 Isaac Sim Docker·기록·학습을 실행하고 노트북이 화면 수신과 USB 리더암 읽기를 담당합니다.
1~6장 학생 Python 파일은 로컬 수업과 동일합니다.
코드를 직접 바꾸는 수업은 [브라우저 편집기 안내](browser-classroom.md)를 따릅니다.
AnyDesk는 데스크탑의 최초 설치·실행기 시작에 사용하고, 수업 중에는 노트북 브라우저에서 편집·재실행합니다.
아래는 데스크탑 터미널에서 직접 실행하는 방법과 노트북 USB 리더암 연결 절차입니다.
WebRTC 클라이언트와 리더암 프로그램은 **노트북의 로컬 터미널**에서 실행합니다.

시험할 때는 노트북 두 대로 같은 구성을 만들 수 있습니다. Isaac Sim을 실행하는 쪽이 **서버**이고,
화면을 받는 쪽이 **클라이언트**입니다. 서버가 서브 노트북이어도 실행 방법은 같습니다.
`remote serve --host`와 화면 클라이언트의 Server에는 모두 **Isaac Sim을 실행하는 PC의 IP**를 입력합니다.

## 1. 준비

- 데스크탑: 루트 README대로 설치·카메라 검사를 완료하고 이 변경이 포함된 코드로 `./lekiwi setup sim`을 실행합니다.
- 노트북: Ubuntu x86_64, Python 3, Docker Engine. 리더암 실습용 이미지에 GPU/CUDA가 필요하지 않습니다.
- 노트북에서 선택한 데스크탑 주소에 도달할 수 있어야 합니다. Tailscale이면 양쪽 연결 상태를, 같은 LAN이면 기기 간 통신 차단 여부를 확인합니다.
- 데스크탑의 WebRTC는 TCP 49100·UDP 47998, 리더 입력/연결 검사는 UDP 49101을 사용합니다.
- `--share-client`를 지정한 테스트에만 HTTP 8766으로 `/client.zip` 한 파일을 제공합니다. 파일 목록과 data는 공개하지 않습니다.
- 서로 다른 망에서는 Tailscale을 사용합니다. 같은 LAN에서는 LAN IP로 직접 연결할 수도 있습니다. 방화벽을 자동 변경하지 않습니다.
- 학생별 데스크탑과 접속 문구를 구분합니다. 리더 입력 인증은 HMAC이며 영상 접속 자체의 로그인 기능은 아닙니다.

Docker에 sudo가 필요한 PC에서는 해당 터미널에서 `export LEKIWI_DOCKER_SUDO=1`을 설정합니다.
Isaac 라이선스에 동의한 데스크탑에서 `export ACCEPT_EULA=Y`를 설정합니다.
아래 `192.168.0.81`은 LAN 주소 예시입니다. **Tailscale을 사용한다면 데스크탑에서 `tailscale ip -4`로 확인한 주소**로 바꿉니다.

## 2. 리더암 없이 1장 화면 확인

데스크탑에서 실행합니다.

```bash
./lekiwi remote serve --host 192.168.0.81 --chapter 1
```

`STUDENT_SCRIPT ready`가 나오면 노트북에서 연결을 검사합니다.

```bash
./lekiwi remote check --host 192.168.0.81
```

이 검사는 TCP 협상·UDP 제어 경로 확인입니다. 영상 전송 성공이나 프레임률을 보증하지 않습니다.
노트북에 [Isaac Sim 5.1용 WebRTC Streaming Client](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/installation/download.html)를 설치하고
클라이언트에서 데스크탑 IP를 입력해 Connect합니다. 라이선스와 Linux 설치 안내는 공식 페이지를 따릅니다.
표준 Stage·Property·Play/Stop이 보이는지, Play 입력이 실제로 전달되는지 확인합니다.

종료는 기록을 저장한 뒤 데스크탑 터미널의 Ctrl+C 또는 스트리밍 화면의 File > Exit를 사용합니다.
다음 장은 `--chapter 2`부터 `--chapter 6`까지 같은 방식입니다. 한 번에 한 실습만 실행합니다.
1장 비교 예제는 `--experiment 2`, 직접 수정한 파일은 `--script 01_object_physics/experiments/01_no_gravity.py`로 선택합니다.
코드는 다음 실행에 반영되며 학생 파일을 수정할 때마다 이미지를 재빌드할 필요는 없습니다.

## 3. USB 없이 관절 입력 전송 검사

데스크탑에서 6장을 시작합니다.

```bash
./lekiwi remote serve --host 192.168.0.81 --chapter 6 --teleop
```

12자 이상의 접속 문구를 정해 숨김 입력란에 입력합니다. 명령 인자·환경 변수·로그·문서에는 기록하지 않습니다.
노트북에서 아래 명령을 실행하고 같은 문구를 입력합니다.

```bash
./lekiwi remote demo --host 192.168.0.81 --seconds 10
```

`accepted`가 증가하고 PASS이면 가상 관절 값의 왕복 통신이 확인된 것입니다.
이 명령은 USB를 열지 않으며 시뮬레이션 팔을 자동 활성화하지 않습니다.
실습 화면에서 R을 눌러야 추종하며 전송 종료 후에는 추종이 해제됩니다.

## 4. 노트북에 리더암 환경 준비

아래는 **노트북의 로컬 터미널**에서 진행합니다. 0장에서는 데스크탑에만 저장소를 받았으므로,
실제 리더암을 연결할 노트북에도 수업 코드를 준비합니다. Isaac Sim·NVIDIA 드라이버를 설치하는 `./lekiwi install`은 노트북용 명령이 아닙니다.

Git·Python이 없다면 설치한 뒤 저장소를 받습니다. 같은 이름의 폴더가 있으면 새로 덮어쓰지 말고
그 폴더에서 `git branch --show-current`와 `git status --short`를 먼저 확인합니다.

```bash
sudo apt update
sudo apt install git python3
git clone --branch feature/remote_classroom --single-branch https://github.com/SJun99/lekiwi_isaacsim.git lekiwi_classroom
cd lekiwi_classroom
git branch --show-current
```

브랜치가 `feature/remote_classroom`인지 확인합니다. 이후 노트북의 `./lekiwi remote ...`는 이 폴더에서 실행합니다.
`docker --version`과 `docker info`로 Docker 설치·접근을 확인합니다.
Docker가 **아직 설치되지 않은 Ubuntu 노트북**은 다음과 같이 Ubuntu 제공 패키지를 준비합니다.
기존 Docker가 있으면 이 설치를 건너뜁니다. [Ubuntu 공식 Docker 설치 안내](https://ubuntu.com/server/docs/how-to/containers/docker-for-system-admins/)

```bash
sudo apt install docker.io
sudo systemctl enable --now docker
```

`docker info`는 권한 오류지만 `sudo docker info`가 성공하면 다음을 설정합니다.
새 터미널에서 리더를 실행할 때도 같은 설정이 필요합니다.

```bash
export LEKIWI_DOCKER_SUDO=1
```

Docker 실행을 확인한 뒤 CPU 리더 이미지를 한 번 빌드합니다.

```bash
./lekiwi remote setup-client
```

CPU 전용 PyTorch와 LeRobot 0.6.1을 격리한 이미지입니다. 최초 다운로드에 시간과 디스크 공간이 필요합니다.
학습용 LeRobot 이미지는 데스크탑에서 별도로 사용합니다.
장치 경로는 노트북에서 `ls -l /dev/serial/by-id/`로 확인합니다.

## 5. 실제 리더암 연결

서버가 리더 입력을 기다리고 있어야 합니다. 브라우저 수업은 저장·종료 후 **브라우저 터미널**에서
`lesson run 6 --teleop`을 실행하고 12자 이상의 접속 문구를 정합니다. `lesson status`의 READY를 확인한 뒤
WebRTC로 접속합니다. 데스크탑에서 직접 실행하는 방식은 위 3절을 사용하며, 두 방식을 동시에 실행하지 않습니다.
이미 `lesson run 6 --teleop`으로 시작한 실습이 READY라면 그 실습과 접속 문구를 그대로 사용하고 실행 명령을 반복하지 않습니다.

리더암이 맞는지 확인하고, 팔을 지지한 상태에서 전원을 바로 끌 수 있도록 준비합니다.
아래 명령의 연결 확인 단계는 리더암 토크를 해제하므로 팔이 떨어지지 않도록 지지해야 합니다.
기존 보정이 있으면 재사용 여부를 직접 선택합니다. 자동으로 토크를 켜거나 팔을 이동시키지 않습니다.

```bash
./lekiwi remote leader --host 192.168.0.81 \
  --port /dev/serial/by-id/실제_리더암_장치 --id student01
```

접속 문구를 입력하고 보정·연결 안내를 따릅니다. 보정 후 시뮬레이션 팔의 방향을 확인하고 R로 활성화합니다.
조작할 때는 **WebRTC 영상 창을 맨 앞으로 가져와 Viewport를 클릭하고 영문 입력 상태**에서 키를 누릅니다.
브라우저 편집기가 선택되어 있으면 R/W 등의 키가 Python 코드에 입력될 수 있습니다.
SPACE는 정지, F8은 장면 초기화·큐브 재배치입니다. 저장하지 않은 기록이 있으면 초기화가 차단됩니다.
F5 기록 시작, F6 종료, F7 연습 저장, F9 성공 저장, F10 두 번은 폐기입니다.
브라우저 수업의 기록 길이는 `01_lekiwi_recording.py`의 `duration_seconds`를 수정하고 실습을 재실행합니다.
데스크탑에서 직접 실행하는 경우에는 실행 전에 `export LEKIWI_RECORD_SECONDS=120` 등으로 설정합니다.

- 보정 JSON: 노트북의 `data/calibration/so101_leader/`.
- 데이터셋·시연·학습 결과: 데스크탑의 `data/`를 컨테이너 `/data`에 연결해 보존합니다.
- 서버 실행 로그와 임시 입력: 데스크탑의 `data/remote/session.*/`.
- 모두 Git에서 제외됩니다. 실제 데이터 기록은 데스크탑의 기존 시뮬레이션 시간·카메라 동기화 경로를 사용합니다.

입력은 서버 요청을 받은 뒤 새로 읽으며, 서버 기준 200 ms가 지난 응답은 반영하지 않습니다.
송신기는 50 ms마다 수신을 확인하되 요청 전체의 200 ms 한도까지 응답을 기다립니다.
핫스팟·Tailscale에서 정상 응답이 50 ms보다 늦게 도착해도 현재 요청을 먼저 취소하지 않습니다.
200 ms 안에 완료하지 못한 요청은 종료하고 다음 주기에 새 관절값을 요청하며, 지난 관절값을 재전송하지 않습니다.
원격 가상 로봇은 마지막으로 수락한 입력의 서버 발급 시각부터 **500 ms**까지 다음 입력을 기다립니다.
500 ms를 넘으면 시뮬레이터가 베이스를 정지하고 팔 목표를 유지합니다. 수신기는 표본 시각을 갱신하지 않고 단절을 표시합니다.
마지막 유효 입력부터 **2초 안에 같은 연결의 새 표본 3개**가 확인되면 팔 추종만 자동 재개합니다.
중복 표본은 세지 않고, 새로 발생한 단절이나 일부 표본 수신으로 기존 복구 제한 시간을 연장하지 않습니다.
베이스 키는 초기화하며 누른 채인 키의 자동 반복으로 다시 출발하지 않습니다. 놓았다가 다시 누릅니다.
2초 경과, 잘못된 입력, 송신 프로그램 재시작, SPACE, 장면 초기화, 영상 연결 종료 이후에는 R이 필요합니다.
복구 첫 프레임은 현재 가상 팔 자세에서 시작하고 밀린 동작을 재생하지 않습니다.
네트워크 경로의 일시적인 오류는 송수신을 다음 주기에 재시도합니다. USB 리더의 읽기 오류는 전파하여 기존 종료 절차를 따릅니다.
소켓 전송 차단이 `EPERM`·`EACCES`로 반환되는 경우도 재시도합니다. 이 처리는 소켓 호출에만 적용하고 USB 읽기 권한 오류는 종료 사유로 유지합니다.
로컬 USB 텔레옵의 250 ms 정지 기준과 실제 리더암의 토크 OFF 설정은 그대로입니다.
화면 연결 종료를 SDK가 감지하면 키 상태를 비우고 추종을 해제합니다.
Wi-Fi 단절을 영상 SDK가 감지하는 시간과 실제 조작 지연은 두 PC에서 측정해야 합니다.
공식 WebRTC 클라이언트의 자동 재접속 기능을 추가한 것은 아닙니다. 영상은 같은 서버 주소로 Connect한 뒤 R로 조작을 재개합니다.
녹화 중 원격 입력 단절 또는 영상 연결 변경을 감지하면 해당 에피소드를 마감하고 미저장 상태로 유지합니다.
F7 연습 저장 또는 F10 두 번 폐기 후 새 F5로 시작하며, 중단된 기록의 F9 성공 저장은 차단합니다.
학생 안내는 [4장 조작 복구](../isaacsim_basic/04_teleoperation/README.md#47-실습-중-늦어지거나-끊기면)와
[6장 녹화 복구](../isaacsim_basic/06_lekiwi_dataset/README.md#기록-중-연결이-끊기면)에 있습니다.

## 6. 배포 전 임시 노트북 파일 전달

아직 Git에 반영하지 않은 구현을 시험할 때 데스크탑 실행에 `--share-client`를 추가합니다.
표시된 `/client.zip`을 노트북으로 내려받아 새 폴더에 풉니다. 기존 저장소에 덮어쓰지 않습니다.
압축은 지정한 실행 소스와 문서만 포함하며 모터 보정·데이터·접속 문구는 포함하지 않습니다.
압축을 풀어 실행 권한이 없다면 `bash lekiwi remote ...`로 실행할 수 있습니다.
서버 종료 시 다운로드 서버도 종료됩니다. 이 파일은 연결 테스트용이며 전체 교재·Isaac 자산을 포함하지 않습니다.

## 구현 근거와 검증

[Isaac Sim 5.1 Livestream Clients](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/installation/manual_livestream_clients.html)와
5.1.0 Docker에 포함된 `standalone_examples/api/isaacsim.simulation_app/livestream.py`를 참고했습니다.
headless·hide_ui 설정을 사용하며 이 LAN 구성에는 WebRTC 확장만 활성화합니다.
학생 파일의 독립 실행 코드는 보존하고 실행기가 첫 SimulationApp 생성에만 원격 설정을 적용합니다.

2026-09-10 개발 PC에서 다음을 확인했습니다.

- 실제 UDP 왕복 전송, 인증 실패·지연 응답·중복 메시지 차단, 입력 만료와 재접속 시 재활성화 요구.
