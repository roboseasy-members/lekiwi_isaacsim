# SO101 calibration과 통합 teleop

실제 SO101 **리더만** USB로 연결한다. 제어 대상 베이스·팔은 Isaac Sim 안에
있다. 실제 follower 또는 LeKiwi 본체를 제어하는 명령은 없다.
실제 리더 보정, 가상 입력의 팔 추종, 개발 PC에서 사용자의 베이스·팔 통합
teleop 확인을 완료했다. 다른 리더/PC의 방향과 영점은 별도로 확인해야 한다.
처음 설치하는 사용자는 루트 README의 순서를 따른다. 아래 날짜별 기록은
개발 당시의 실패와 후속 검증을 함께 보존한 이력이다.

## 실행

변경된 코드를 이미지에 반영하려면 먼저 `./lekiwi setup all`을 실행한다.
Docker에 sudo가 필요하면 각 명령 앞에 `LEKIWI_DOCKER_SUDO=1`을 붙인다.

보정만 실행:

```bash
./lekiwi calibrate --port /dev/serial/by-id/본인_리더_장치 --id my_so101
```

보정 확인과 베이스·팔 teleop을 한 번에 실행:

```bash
ACCEPT_EULA=Y ./lekiwi teleop --port /dev/serial/by-id/본인_리더_장치 --id my_so101
```

두 명령을 순서대로 반드시 실행할 필요는 없다. teleop 자체에 보정 절차가 포함된다.
`--id`는 같은 팔에 대해 계속 동일하게 사용한다. 포트는 `/dev/ttyACM0` 등도
가능하지만 연결 순서가 바뀌어도 식별 가능한 `/dev/serial/by-id/` 경로를 권장한다.

## 기존 파일이 있으면 항상 질문

저장 경로는 `data/calibration/so101_leader/<id>.json`이다. 보정 파일이 있으면
모터와 이미 일치해도, calibrate와 teleop **모두 실행할 때마다** 아래 질문을 한다.

```text
Press ENTER to use provided calibration file associated with the id my_so101, or type 'c' and press ENTER to run calibration:
```

- `c` + Enter: LeRobot 보정 절차 실행. 기존 파일은 백업하고 새 파일은 검증 후 교체.
- Enter: 기존 파일을 검사한 뒤 모터에 적용하고 읽어 확인. 새 범위 측정은 하지 않음.
- `q`: 장비 연결 전에 취소.
- 잘못된 입력: 다시 질문. 입력이 끊기면 취소하며 자동 선택하지 않음.

파일이 없으면 새 보정이 필요하다. 기존 보정 파일이 다른 폴더에 있으면 위 경로로
검토 후 가져올 수 있지만, 다른 팔의 파일을 자동 검색해서 사용하지 않는다.
손상된 파일에서 Enter로 재사용을 선택하면 오류로 종료한다. 재보정 실패 시 기존 파일을
유지하지만, 중간에 모터 설정이 바뀌었을 수 있으므로 다시 검증해야 한다.

연결 전 팔 낙하 방지를 위해 받친 상태와 전원 차단 가능 여부를 확인한다.
시작 확인은 `준비`라는 단어 대신 Enter를 누른다. 그 뒤에만 LeRobot이
연결·토크 해제·설정 기록을 한다. 취소하려면 Ctrl+C를 누른다.
중간 자세, 관절 범위 측정 등 물리 작업은 터미널 안내에 따라 한 단계씩 수행한다.
리더 토크 활성화나 목표 위치 명령은 보내지 않는다. 연결 실패 시 상태를 추측하지 않는다.

## 조작과 좌표 대응

GUI가 뜨더라도 보정 전 또는 `R`을 누르기 전에는 베이스·팔 teleop이 비활성이다.
뷰포트에서 `R`을 누르면 가상 팔이 리더의 현재 절대 각도를 목표로 움직인다.

- `W/S`, `A/D`, `Q/E`: 기존 베이스 조작.
- `1/2/3` (숫자패드 포함): 베이스 속도 기존 / 1.5배 / 2배. 시작 단계는 `1`.
  이동 속도는 0.25 / 0.375 / 0.5 m/s, 회전 속도는 0.8 / 1.2 / 1.6 rad/s.
  화면에 현재 단계가 표시되며, 키를 누른 채로도 전환된다. 팔 추종 속도는 그대로다.
- `R`: 절대 자세 추종 활성화. 현재 가상 팔 자세에서 리더 자세로 빠르게 수렴하며 순간 이동하지 않음.
- `Space`: 베이스 정지, 팔 목표 유지, teleop 비활성화. 다시 `R` 필요.
- 창 닫기 또는 실행 터미널 `Ctrl+C`: 이번 실행이 만든 두 컨테이너 종료.

팔 5개 관절은 `목표 = 방향 × 리더 절대각 + 영점 보정값`을 degree→radian으로
변환한다. `R`을 누른 시점의 리더 각도를 빼지 않는다. 그리퍼는 0..100%를
0..1.5 rad로 대응하며 방향이 -1이면 여닫힘을 반전한 뒤 영점 보정값을 더한다.
목표 변화 속도 기본값은 **실제 경과 시간 기준 3 rad/s**다. 한 프레임에 반영하는
시간은 최대 50 ms다. 화면 갱신이 늦더라도 최신 리더 표본이 유효하면 활성 상태를
유지하며, 지연 시간을 몰아서 적용하지 않는다. 250 ms 기준은 **리더 표본의 나이**에
적용한다. 오래된 표본·연결 끊김·잘못된 데이터·역행하는 시계는 비활성화 후 `R`을 다시 요구한다.
USD 관절 한계를 넘는 목표는 제한하고 화면에 `LIMIT` 관절명을 표시한다.
이는 목표각 제한이며 실제 관절 속도/충돌 안전을 보장하는 기능은 아니다.
렌더링이 아주 느리거나 물리 엔진의 지연이 있으면 완전한 실시간 일치는 보장되지 않는다.

관절 방향 기본값은 모두 +1이며 실제 리더와 한 관절씩 검증해야 한다.
반대 방향인 관절은 `LEKIWI_ARM_SIGNS=1,-1,1,1,1,1`처럼 지정할 수 있다.
순서는 shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper다.
영점 보정 기본값은 `LEKIWI_ARM_OFFSETS_DEG=0,0,0,0,-90,0`, 속도는
`LEKIWI_ARM_MAX_SPEED=3.0`으로 설정한다. 속도 허용 범위는 0 초과 10 이하 rad/s다.
집게가 양옆으로 배치되도록 `wrist_roll`에 -90°를 적용한다. 방향 기준은
손목에서 집게 끝을 바라볼 때 시계방향이다. 시작 자세와 리더 추종에 모두 적용하며,
`R`을 눌러도 이 보정값은 유지한다. 모터 calibration 파일이나 URDF/mesh는 변경하지 않는다.
기존 `.env`에서 여전히 `0,0,0,0,0,0`을 지정했다면 -90° 기본값을 덮어쓰므로 수정해야 한다.
손목 보정을 적용하면 리더의 음수 회전 쪽에서 모델 한계에 더 일찍 닿을 수 있다.
기본 방향과 보정값은 실물 자세의 완전한 일치를 보장하는 프리셋은 아니다.
관절별 방향과 영점은 실물과 화면을 비교해 검증해야 하며, LeRobot 모터 보정과
모델 영점 맞추기는 별개다. 한계 범위 밖의 리더 자세는 완전히 복제할 수 없다.

로컬 USB에서는 250 ms 이상 오래된 표본, 연결 끊김, 잘못된 단위/숫자/세션은 teleop을 해제한다.
회복해도 자동 재개하지 않는다. GUI가 멈춘 동안은 물리 스텝도 진행되지 않으며,
다음 제어 스텝에서 watchdog을 검사한다. 리더는 읽기 실패를 자동 재시도하지 않는다.

원격 가상 로봇은 별도 기준을 사용한다. 500 ms 입력 공백에서 정지하고 마지막 입력부터 2초 안에
같은 연결의 새 표본 3개를 확인하면 팔 추종을 재개한다. Space·영상 종료·긴 끊김 이후에는 R이 필요하다.
실습 중 대처는 [4장 통신 복구](../isaacsim_basic/04_teleoperation/README.md#47-실습-중-늦어지거나-끊기면)를 따른다.

## 구현 구조와 검증 범위

LeRobot 컨테이너가 30 Hz로 리더 위치를 읽고, `data/teleop/session.*/leader.json`을
원자적으로 교체한다. Isaac 컨테이너는 최신 표본을 읽는다. 네트워크 포트/ROS 없이
같은 PC의 Docker bind mount와 monotonic clock을 사용한다. 이는 **최신 값만 유지하는
teleop 통신**이므로 향후 데이터셋 기록을 이 파일 변경 이력으로 구현하면 안 된다.
GUI 로그는 해당 세션의 `sim.log`에 남는다. 세션마다 새 디렉터리를 사용한다.

실제 리더 방향·USB 재연결·통합 GUI 조작은 사용자와 함께 추가 검증해야 한다.
원본 API는 [LeRobot 0.6.1 SOLeader](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/teleoperators/so_leader/so_leader.py)를 사용한다.

### 2026-09-07 구현 검증

- 자동 테스트 50개 통과: 기존/신규 보정 분기, 명시적 선택, 백업·실패 시 원본 유지,
  모터 읽기 검증 실패, 단위·숫자·세션 검사, 상대 관절 대응·속도/범위 제한,
  watchdog·재활성화, 제한된 USB 전달 등을 검사했다. 실제 모터는 mock으로 대체했다.
- 두 Docker 이미지 재빌드, 이미지 내부 CLI 도움말 및 설치된 SO101 API 확인 통과.
- 실제 USB 식별 경로를 확인했지만 장치를 열거나 보정/토크 명령을 보내지 않았다.
- `ACCEPT_EULA=Y ./lekiwi test-arm`은 가상 입력으로 6개 관절 추종을 검사한다.
  이번 실행은 로봇 생성 전 Vulkan `vkCreateDevice`/`ERROR_INITIALIZATION_FAILED`에서
  중단됐다. 호스트 커널에도 NVIDIA Xid 32가 기록됐다. 따라서 **실제 Isaac 팔 추종은
  아직 통과로 보고하지 않는다**. GPU 상태 복구 후 test-arm과 test-physics,
  통합 GUI 조작을 재검증해야 한다. 재부팅/드라이버 초기화는 자동 수행하지 않는다.

### 같은 날 후속 검증

- 사용자가 실제 SO101 보정을 완료했고 `so101_leader.json`의 6개 ID·범위 검사를 통과했다.
- Vulkan 초기화가 다시 통과했다. 드라이버 설정 변경이나 재부팅은 수행하지 않았으며,
  이전 오류의 영구 해결을 의미하지는 않는다.
- 실제 팔 검사에서 `WheeledRobot.post_reset()`이 전체 관절의 위치 제어 gain을
  0으로 바꾸는 문제를 재현했다. reset 후 팔 6개에만 gain을 복구하도록 수정했다.
  USD의 degree 기준 gain은 PhysX tensor API의 radian 기준으로 변환한다.
  바퀴와 수동 롤러 gain은 변경하지 않는다.
- 수정 후 `test-arm`의 6개 관절 추종 검사 통과. 최대 오차 약 0.0018 rad.
  단위 변환 및 바퀴/롤러 gain 보존 검사 포함 자동 테스트 55개 통과.
- 기존 베이스 물리 회귀검사도 재통과: 전진 0.22832 m, 좌측 0.23298 m,
  반시계 회전 0.78453 rad.
- GUI 실행 시 세션 폴더의 `sim.json`에 활성 상태·목표/실제 관절값(rad)을
  진단용으로 기록한다. 리더 방향 검증이나 손 움직임 확인을 대신하는 것은 아니다.

### 절대 자세·추종 속도 변경 검증

- 상대각 계산을 제거했다. `R`은 추종만 활성화하며 리더 영점을 다시 잡지 않는다.
- 기본 목표 변화 속도를 3 rad/s로 변경하고 실제 경과 시간을 사용한다.
  20/30/60/120 FPS에서 0.2초 동안 목표가 동일하게 0.6 rad 변하는 테스트를 통과했다.
- 자동 테스트 66개 통과. 방향·영점 설정, 관절 제한, 프레임당 변화 제한,
  긴 GUI 지연 시 비활성화와 재활성화 요구, 기존 보정 분기를 포함한다.
- 수정 이미지의 `test-arm` 통과: 6개 관절 최대 오차 약 0.0018 rad.
  30 FPS를 재현한 비영점 리더 자세에서는 2초 후 최대 오차 약 0.0006 rad.
  이 오차는 제한된 목표와 가상 팔 사이의 값이며 실물 자세 일치 검증은 아니다.
- `sim.json`에 최종 목표 `goals`와 제한된 관절 `clipped`를 추가했다.
  `targets`는 속도 제한을 적용한 현재 명령이다. 모두 관절각은 rad 기준이다.
- 리더 방향·모델 영점과 실제 손 움직임에 대한 통합 검증은 사용자 확인이 필요하다.

### 화면 지연으로 인한 반복 비활성화 수정

화면 갱신 간격이 250 ms를 넘으면 최신 리더 표본이 있어도 비활성화되던 조건을
제거했다. 통신 검사에는 기존 250 ms 표본 유효 기간을 그대로 사용한다.
지연 이후에도 목표 변화는 한 번에 최대 50 ms분(기본 속도에서 0.15 rad)만 적용한다.
실제 표본 만료·연결 끊김·Space 이후에는 자동 재개하지 않는다.
자동 테스트 83개 통과: 0.251/0.3/1/5초 GUI 지연, 지연과 실제 통신 이상이 겹친 경우,
시계 이상, 기존 속도 단계·손목 보정·보정 파일 보호를 포함한다.
이 수정은 렌더링 성능 자체를 개선하는 변경은 아니다.
